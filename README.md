# Розклад ЛНУ — прототип

Статичний сайт розкладу для ЛНУ імені Івана Франка: HTML, CSS і чистий JavaScript (ES-модулі).
Тут немає фреймворків, npm і кроку збирання. Дані беруться з `data.json`, що лежить поруч з `index.html`.

- **Мій розклад.** Користувач один раз вибирає групу, підгрупу, вибіркові дисципліни та викладача англійської. Далі розклад відкривається одразу, з поділом на день і тиждень.
- **Аудиторія.** Показує всі пари в аудиторії за день або тиждень, разом із вільними слотами.
- **Викладач.** Показує всі пари викладача.

Режими «Аудиторія» і «Викладач» будуються інвертуванням групових розкладів з `data.json`.
Якщо в даних є не всі групи, сайт прямо показує, що дані неповні.

```
site/                  ← цю теку копіюємо на сервер
  index.html
  data.json
  assets/app.css, icon.svg
  js/
    main.js            точка входу: завантаження, маршрути, контекст екранів
    config.js          вибір джерела даних (static | api)
    prefs.js           localStorage: група, підгрупа, вибіркові, викладач англійської
    lib/               text.js (нормалізація й пошук), dates.js
    domain/            parse.js (поля деканату), lessons.js (модель Lesson), electives.js (фільтр «мого розкладу»)
    data/              psrozklad.js (формат експорту), static-repository.js, api-repository.js (ескіз), repository.js
    ui/                екрани: view-my, view-lookup (аудиторії/викладачі), view-settings; schedule.js — спільний рендер
deploy/nginx.conf      приклад конфігурації nginx
tests/                 юніт-тести (node --test, без залежностей)
```

## Запуск

**Локально:**

```sh
cd site
python3 -m http.server 8000
# http://localhost:8000/
```

Для демо можна «перевести годинник» параметром `?now=`:
`http://localhost:8000/?now=2026-09-28T10:40`. Тестові дані охоплюють тиждень 28.09–02.10.2026.
З цим параметром видно поточну пару, наступну пару й «вікна» між ними.

Тести запускаються з кореня репозиторію командою `node --test`. Потрібен Node 22+, npm не потрібен.

**На сервері (nginx):**

```sh
rsync -a --delete site/ server:/var/www/rozklad/
```

Далі підключіть [`deploy/nginx.conf`](deploy/nginx.conf). Для `data.json` там стоїть `Cache-Control: no-cache`:
браузер щоразу ревалідує файл і отримує 304, тож нове `data.json` підхоплюється одразу.
Щоб оновити дані, достатньо атомарно замінити файл (записати в `data.json.tmp` і зробити `mv`).

Усі шляхи відносні, а маршрути живуть у hash (`#/my`, `#/rooms/…`). Тому сайт працює в підкаталозі (`/rozklad/`)
без додаткових налаштувань; приклад з `alias` є в кінці конфігу. Так само працюють Caddy (`file_server`) і GitHub Pages:
достатньо опублікувати вміст `site/`, наприклад через Pages з GitHub Actions і `path: site`.

## Шар даних

UI звертається лише до об'єкта-репозиторію з асинхронними методами. Звідки прийшли дані, UI не знає.

```
getMeta()                             діапазон дат, покриття (скільки груп є), час оновлення, «дзвінки»
listGroups() / findGroup({id, name})
getGroupSchedule(groupId, {from, to}) → { group, lessons }
listRooms() / getRoomSchedule(key, range)
listTeachers() / getTeacherSchedule(key, range)
refresh()                             перевірити, чи змінилися дані
```

- **`StaticRepository`** (зараз). Завантажує `data.json` один раз, будує індекси груп, аудиторій і викладачів.
  Пари однієї потокової лекції з різних груп об'єднує в одну. Без мережі показує останню збережену копію
  з localStorage і повідомляє про це. Коли вкладка знову стає активною і минуло понад 10 хвилин, перевіряє оновлення.
- **`ApiRepository`** (ескіз у `data/api-repository.js`). Має той самий інтерфейс поверх нашого API
  (`GET groups/{id}/schedule?from&to` тощо). Щоб перейти на нього, достатньо змінити один рядок у `js/config.js`:
  `{ kind: 'api', baseUrl: 'api/' }`. UI переписувати не треба.
- Екрани працюють з нормалізованою моделлю **`Lesson`** (`domain/lessons.js`), а не з сирими записами деканату.
  Модель містить дату в ISO, номер і час пари, нормалізовану назву, тип, `teacher {name, short, position, key}`,
  `room {label, building, lab, key}`, `audience {kind: subgroup|stream|mixed|whole|other, subgroups}`, заміну,
  онлайн-посилання та стабільний `id`. `id` — це хеш ключових полів; майбутній збирач зможе використати його для diff і сповіщень про заміни.
- Розбір полів (`domain/parse.js`) і фільтр «мого розкладу» (`domain/electives.js`) — чисті функції.
  Їх можна перенести в бекенд-збирач без змін.

### Формати `data.json`

1. **Сирий експорт деканату**, як зараз: `{"psrozklad_export": {"roz_items": [...], "code": "0"}}`.
   У ньому може бути одна група або кілька, групи визначаються за полем `object`. Можна подати й масив таких експортів.
2. **Пакет**. Це формат, у якому майбутній збирач може викладати статичний знімок; кожна частина — сира відповідь деканату:

```json
{
  "format": "lnu-rozklad-bundle/1",
  "generated_at": "2026-09-26T06:00:00Z",
  "range": { "from": "01.09.2026", "to": "31.12.2026" },
  "lists": { "group": <obj_list group>, "teacher": <obj_list teacher>, "room": <obj_list room> },
  "schedules": [
    { "mode": "group",   "id": "-503", "name": "ФЕІ-21с", "fetched_at": "…", "export": <rozklad> },
    { "mode": "teacher", "id": "-77",  "name": "…",       "export": <rozklad> }
  ]
}
```

Якщо в пакеті є `obj_list` груп, сайт знає, скільки груп мало б бути, і пише «розклад 12 з 340 груп».
У виборі групи він позначає, для яких груп даних немає. Коди помилок деканату теж показуються:
`-2`/`-3` означає «розклад ще складається», `-8` — «пауза», `-70` — «помилка дат». Розклади викладачів (`mode: teacher`)
у пакеті дають змогу додавати сторонні ДВВС, яких немає в жодному груповому розкладі.

## Як працює «мій розклад»

- Пари `(підгр. N)` фільтруються за вибраною підгрупою. Якщо вибрано «Усі», показуються пари всіх підгруп з позначками.
- Пари з позначкою «Потік», із порожнім полем `group` та з іншими значеннями цього поля показуються всім.
- Пари «Збірна група» за замовчуванням приховані. Виняток:
  - **Іноземна мова.** Користувач вибирає свого викладача. Мову розпізнаємо за назвою, а якщо в `obj_list` є кафедри — ще й за кафедрою викладача.
  - **Вибіркові.** Користувач сам позначає, які відвідує. Якщо дисципліну ведуть кілька викладачів (наприклад, лабораторні в різних слотах), можна вибрати своїх.
  - Над розкладом є рядок «Приховано N пар „Збірна група“ · Показати». Приховані пари там можна побачити й одним дотиком позначити «Це моя пара».
- **Сторонні дисципліни.** Користувач шукає викладача і вибирає дисципліну з його розкладу. Її пари додаються до «мого розкладу» без дублів.
- Бронювання (`reservation`) показуються як зайнятий слот з назвою. Слот без назви позначається як «можливо, ДВВС».
- Якщо заповнені `replacement`, `online`, `link`, `comment` чи `half`, вони виводяться на картці.
  Заміна виділяється червоним, посилання стає кнопкою (дозволені лише http/https).
- Без дати в адресі сайт показує сьогодні, якщо ще є пари. Інакше він показує найближчий день з парами і пояснює чому.
  Дні між парами показуються як «вікна». Поточна пара підсвічується з прогресом, наступна — з відліком «через N хв».
- На телефоні дні гортаються свайпом, на комп'ютері — стрілками ←/→. Світла чи темна тема береться з налаштувань системи.

## Припущення щодо даних

- Усі поля — рядки. Дата має формат `дд.мм.рррр`, час — `HH:MM-HH:MM`. `lesson_name` дублює номер пари, і для логіки використовується `lesson_number`.
- **Викладач.** ПІБ — до трьох останніх слів з великої літери, усе перед ними вважається посадою («в.о. зав. кафедрою»).
  Крапку в кінці прізвища прибираємо: «Горон.» і «Горон» — одна людина. Ініціали на кшталт «Б.З.» не чіпаємо.
  Викладача ідентифікуємо за нормалізованим ПІБ, бо ID викладача в записах пар немає.
- **Аудиторія.** Прибираємо пробіли й NBSP, латинські літери-двійники замінюємо кириличними (`129a/T` → `129а/Т`).
  Префікси `№`/`N`/`No` вважаємо одним позначенням лабораторії: `N10/Б` = `№10/Б`. Водночас `№5/Б` і `5/Б` вважаємо **різними** приміщеннями.
  Пошук знаходить обидва варіанти.
- **Назва.** Подвійні пробіли та «висячу» крапку прибираємо («…сервера .» → «…сервера»). Дисципліни порівнюються без урахування регістру і кінцевих розділових знаків.
- **Поле `group`.** `(підгр. N)` означає підгрупу (номерів може бути кілька), «Потік» — спільну лекцію, «Збірна група» — англійську або ДВВС.
  Порожнє поле з `reservation` означає бронювання, порожнє поле без `title` — слот без назви. Будь-що інше показуємо всім як є.
- **Шифр групи** (`ФЕІ-21с`: курс 2, група 1, денна; `М` у кінці серії з 4+ літер — ймовірно магістратура).
  Це лише підказка в списку груп, на неї нічого не спирається. `ФЕМ` вважаємо бакалавратом.
- **ДВВС.** Мітку «ймовірно ДВВС» ставимо, якщо всі пари дисципліни припадають на 3–4 пару вівторка чи п'ятниці. Це теж лише підказка.
- Для сирого експорту діапазон знімка — це повні тижні від першої до останньої пари. «Пар немає» (день у межах знімка)
  і «Немає даних» (день поза знімком) — різні стани.
- «Дзвінки» (час кожного номера пари) беруться з даних, не з хардкоду. Незайняті слоти аудиторії при неповних даних
  позначаються «пар у наявних даних немає», а не «вільно».
- Час «дані оновлено» береться з `generated_at` пакета, а для сирого експорту — з `Last-Modified` відповіді на `data.json`.
  Значення до 2000 року ігноруються.

## Що з майбутнім бекендом

Архітектура не заважає йому.

- Збирач може використати `data/psrozklad.js`, `domain/parse.js` і `domain/lessons.js` без змін.
  Там уже враховано коди помилок, і для кожного коду є прапорець `keepPrevious`: `-2`/`-3`/`-8`/`-70` не повинні перезаписувати знімок.
- Стабільний `Lesson.id` і `sameLessonKey()` придатні для diff між знімками.
- Сайт ніколи не звертається до деканату, він читає лише `data.json` або наш API.
